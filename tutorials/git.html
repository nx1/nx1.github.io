List branches: [^]

git branch --list        # local only
git branch --list -all   # remotes too

Create new local branch [^]

> git checkout -b newbranch
# or with git switch:
> git switch -c newbranch

Switch to existing branch [^]

> git checkout branch_name
# or with git switch:
> git switch branch_name

Push new branch to remote [^]

> git push -u origin newbranch

How to incorporate changes from master branch into current branch [^]

Option 1: 
> git checkout mybranch
> git merge master_branch
Option 2: 
> git checkout mybranch
> git rebase master_branch
Option 3: 
git checkout mybranch
git stash push -m 'wip tree branch before pulling'
git pull --rebase origin master_branch
# fix any merge conflicts
git stash pop

How to combine changes on a local branch with a remote branch and push them [^]

Assuming you already have commited the changes locally. stash uncommited changes. 
> git stash
fetch and merge changes from remote branch 
> git fetch origin staging
> git merge origin/staging
push to local branch as specified remote branch. 
> git push origin sb_tree:staging
unpop changes if needed: 
> git stash pop

Removing old unused Branches. [^]

First check the branch you are going to delete for diffrences between it and the branch you want to keep (i.e. master) 
> git log master..origin/display_collection_name --oneline
If this line returns anything, it means that there are commits that exist on the old branch that do not exist on the master branch. (If you want to know the other way, just flip the order of the branches i.e. 
git log origin/display_collection_name..master --oneline   # This will return much much more haha.
In this case it returned the following: 
3215915 (origin/display_collection_name) gui stuff
To see what those changes were explicitly, one can do: 
git show 3215915
Once happy with the state of the code, the branch may be deleted using: 
# Delete a local branch
git branch -d branch_name      # safe - refuses if unmerged
git branch -D branch_name      # FORCE DELETE REGARDLESS!!!

# Delete from remote (GitLab)
git push origin --delete branch_name

Renaming old unused branches [^]

Sometimes there can be old branches that we do not want to delete, case in point we have an old branch called "main" from before we showed up, this guy is still cluttering both gitlab and git, We don't want to delete it exactly but we don't want it there because it is slightly confusing. We can rename the brach locally by doing: 
git branch -m main archive/main-old
Then we can push the renamed branch by doing: 
git push origin archive/main-old
Finally, we can delete the old branch meaning it no longer clogs shit up: 
git push origin --delete main

Cherry pick merge request [^]

Problem: we add something to merge staging but we don't want to merge in everything, only that specific change we've made. 1. find the commit hash of the commit on staging 
> git log
copy the hash, e.g: 832cdd9ce0f12ba57dae2eac74d7aad6c2d5bfb0 2. change to the branch you want to create the merge request into and pull latest changes: 
> git checkout master
> git pull origin master
3. Create a new branch off the master branch for the merge request. 
> git checkout -b update-docker-compose
4. Cherry pick the commit we want 
> git cherry-pick 832cdd9ce0f12ba57dae2eac74d7aad6c2d5bfb0
x1@Normans-Mac-mini:~/projects/matoha-smartbench$ git cherry-pick 832cdd9ce0f12ba57dae2eac74d7aad6c2d5bfb0
Auto-merging docker-compose.yml
[update-docker-compose 89a2144] Removed deploy policy from docker compose to prevent container restarts on unclean shutdowns
 Date: Mon Jun 1 09:39:57 2026 +0100
 1 file changed, 13 insertions(+), 48 deletions(-)
5. Push the new branch to the master. 
git push origin update-docker-compose
6. Create the merge request on github/gitlab

Temporarily sync a branch with another [^]

Problem: You've created a branch and have got everything right on it but in order to test / build on CI it needs to be on a specific named branch. e.g: I want merge_staging to match master_staging for a bit then i want to revert merge_staging back to how it was. 1. Get the commit hash for merge_staging 
> git rev-parse merge_staging
43996b0e8a894dc2abec361d9bc4fb01058f4923
or: 
> git log -1 merge_staging
and the commit hash will be there in the first line: 
x1@Normans-Mac-mini:~/projects/matoha-smartbench$ git log -1 merge_staging
commit 43996b0e8a894dc2abec361d9bc4fb01058f4923 (origin/merge_staging, merge_staging)
2. Create an immutable local safety tag. 
> git tag merge_staging_backup merge_staging
Make sure the tag was created: 
> git rev-parse merge_staging_backup
43996b0e8a894dc2abec361d9bc4fb01058f4923
3. Switch to merge_staging branch 
> git checkout merge_staging
4. make merge_staging match master_staging 
> git reset --hard master_staging
This moves the branch pointer for merge_staging to match master_staging verify the match with 
x1@Normans-Mac-mini:~/projects/matoha-smartbench$ git log -1 --oneline
9ad49eb (HEAD -> merge_staging, origin/master_staging, master_staging) chore: remove extraneous debug utilities and test media from master_staging
5. Push the updated branch to gitlab 
> git push --force-with-lease origin merge_staging
Why --force-with-lease? • Because master_staging has a different history from merge_staging, Git requires a "force" push. • Plain --force blindly overwrites the server. • --force-with-lease is the safety-enhanced version: it will only overwrite the server if no one else has pushed unexpected commits to origin/merge_staging in the meantime. 6. Make sure the builds complete on gitlab, perform the testing. 7. Revert merge_staging back once testing is complete: 
> git checkout merge_staging
> git reset --hard merge_staging_backup
Verify the restoration: 
> git log -1 --oneline
Expected output: 
43996b0 feat(decision_tree): enhance simulation CLI with interactive and batch modes
8. Push the restored state back to GitLab: 
> git push --force-with-lease origin merge_staging
9. Switch back to master_staging: 
> git checkout master_staging
10. (Optional) Delete the temporary backup tag: 
> git tag -d merge_staging_backup
Deleted tag 'merge_staging_backup'

Sync local commits with remote when remote has moved ahead (Conflict-Safe) [^]

Problem: You have local commits on your branch. Meanwhile, commits have landed on the remote branch. You need to combine both without getting trapped in merge conflict hell. Rule 1: Never do a blind "git pull". Always fetch and inspect first. 1. Stash any uncommitted dirty files: 
> git stash
2. Create a safety backup branch of your exact current state: 
> git branch backup-wip
(Zero-cost safety net. If anything goes sideways, your work is 100% recoverable.) 3. Fetch remote updates without touching your working tree: 
> git fetch origin <branch_name>
4. Inspect the divergence: 
# See what they added that you don't have:
> git log --oneline HEAD..origin/<branch_name>

# See what you added that they don't have:
> git log --oneline origin/<branch_name>..HEAD

# Check which files both sides touched (potential conflict zones):
> git diff --stat HEAD...origin/<branch_name>
5. Combine the changes: Option A: Standard Merge (Recommended when you have multiple local commits) Resolves all conflicts in ONE single pass rather than repeating for each commit: 
> git merge origin/<branch_name>
If conflicts occur: - Run "git status" to see conflicted files ("both modified"). - Open files, search for "<<<<<<<", resolve the logic. - If it's a huge mess and you want to bail out cleanly: 
> git merge --abort
(Instantly resets your branch to before the merge started). Option B: Rebase (Cleaner history, best for 1-2 small local commits) 
> git rebase origin/<branch_name>
If conflicts occur during rebase: - Fix conflict in the file. - git add <file> - git rebase --continue - To bail out completely: 
> git rebase --abort
6. Verify tests and build before pushing: 
> pytest
> git status
7. Push to remote: 
> git push origin <branch_name>
8. Clean up: 
> git stash pop             # restore uncommitted edits if stashed in step 1
> git branch -D backup-wip   # delete temporary safety branch once verified
